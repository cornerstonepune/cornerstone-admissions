- **2026-11-26 · spec** — #63 / PR #75 failed loop-guard on budget (5 files / 63 lines vs files<=4 lines<=40). The ticket itself ordered ~33 deleted lines in `themed-toaster.tsx` plus a `changes/` fragment; the budget counted neither, so it was impossible as written. Durable fix: #63 re-budgeted to files<=5 lines<=65 (issue + PR body). Rule: when setting a Budget, count deleted lines (the guard counts them) and the `changes/` fragment as a file and its lines.
- **2026-11-26 · proof** — `GET /api/ai/usage > flags truncation…` timed out at 5s (fails alone too, ~8s). Root cause is product code, not the test: `zonedParts` in `src/lib/ai/usage-days.ts` builds a new `Intl.DateTimeFormat` per row, 10k rows = 7.5s vs 0.25s cached, so the live endpoint is that slow too. Durable fix: the test gets a 30s timeout (assertions unchanged); a ticket caches the formatter per zone. Rule: a test that is slow because of the code it calls is a perf bug, so file it, don't only raise the timeout.
- **2026-11-26 · process** — A seed fix landed after the build branch had already merged main. Rule: merge main into `plan/t<N>`, then set the ticket's `Plan-base` to that new tip. Never cherry-pick a seed fix onto the build branch: the build branch must stay a descendant of the seed, or the PR diff and budget are measured against the wrong base.
- **2026-11-25 · proof** — Hidden `tests/holdout/db/rls.test.ts` (written for 101) inserted a `settings_changes` row by hand in `fill()`. Once 105's audit trigger landed, the setting insert wrote one too: 2 rows, and 2 tests failed on PR #38 (#26). Durable fix: `fill()` relies on the trigger. Fixed on seed `plan/t26`, not on main, so main stays green until 105 merges. Rule: when a ticket adds a trigger, re-prove every existing test that writes to that trigger's tables against the real migration, in the same seed.
- **2026-11-25 · spec** — #22's spec checked only each row's own `account_id`; reviewer of PR #29 found FKs bypass RLS (cross-account links + id probing), agents could forge stage history and free the one-send slot. Durable fix: ADR 0013, #24/#25 extended, #30 added, `tests/db/rls-refusals.test.ts`. Rule: an RLS spec lists every FK column of the table and says how its target's account is checked.
- **2026-11-25 · spec** — M0 seed drafts asked for RLS policies only, but this Supabase grants `authenticated` nothing on new tables/views, so #22's tests could never pass ("permission denied") and #27's RLS test needs #22. Caught by running the seeds red→green with a reference migration before pushing. Durable fix: ADR 0012 (explicit grants in every migration), stubs and issues #22/#27 updated, #27 blocked by #22. Rule: always prove a seed green with a throwaway reference before pushing.
- **2026-11-25 · tooling** — loop `init.sh` 0.8.4 exits halfway in a repo with no `*tokens*.css`: `grep -v` on empty input returns 1 under `set -euo pipefail`. Durable fix: `|| true` on the `OWN=$(…)` line in the plugin (nimishshah1989/loop). Worked around with a patched copy.
- **2026-11-25 · upstream test** — `GET /api/ai/usage > flags truncation once the row cap is exceeded` takes ~3s alone and ~6s on a busy machine, over Vitest's 5s default, so `npm test` can flake. If it fails in CI, raise that test's timeout in a plan PR. Don't retry blindly.
- **2026-11-25 · process** — #22 builder failed twice without running a check: `loop build` allows only `Bash(<program> *)`, so commands starting with `(`, a heredoc or `python3 -` are refused, and the builder then assumed all Bash was off. Worked on attempt 3 with an explicit ticket "Don't" line. Durable fix needed in the plugin's BUILDER_RULES (nimishshah1989/loop).
